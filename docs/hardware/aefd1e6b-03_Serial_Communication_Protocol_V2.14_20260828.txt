Communication protocol

Summary

This protocol defines the data communication protocol between the external equipment of the stabilization gimbal (including flight control computer, mission computer, etc.) and the optoelectronic gimbal. The physical communication channels include LAN and UART.

Image transmission

The video data can be pushed to the external device by using Rtsp.

Control transfer

The control data can be transmitted to the gimbal via UART or network (UDP), but these two methods cannot operate simultaneously.

Protocol

Interface specification

Network

UDP is the default protocol with port number 9554.

UART

1)  Physical interface: UART 3V3;

2)  Transmission direction: External device->gimbal;

3)  Data content: includes gimbal control commands, aircraft information, and joystick data.

4)  Serial port configuration: 1-bit start bit, 8-bit data bit, 1-bit stop bit, no parity bit, baud rate 115200 bps.

5)  Communication frequency: 25Hz;

Communication protocol for external devices to the gimbal

The peripheral device issues commands at 25Hz (40ms intervals) in a fixed cycle, with control commands fixed at 44 bytes. The frame format is shown in Table 1.

  Table 1 Control command frame format of the hangar

  --- --- --- --- --- --- --- --- ----- ---- ---- ---- ---- ---- ---- ---- ----
  1   2   3   4   5   6   7   8   ……    37   38   39   40   41   42   43   44

  A       B   C       D       E              F    G         H         I    J
  --- --- --- --- --- --- --- --- ----- ---- ---- ---- ---- ---- ---- ---- ----

a)  A: Synchronization code, FB, 2C.

b)  B: Standard command codes (1 byte). Refer to Table 2, 'gimbal Control Command Codes Table,' for definitions of specific codes in the sections on payload utilities, visible light payload, infrared payload, and gimbal functions. Standard command codes issue routine control commands to the gimbal. For parameterized commands, the parameters are defined in fields C and D.

c)  C: Parameters 1 and 2 are 1 and 2 bytes respectively; refer to Table 3 "Conventional Control Command Parameters Table" for specific meanings.

d)  D: Parameter 2, 2 bytes; see Table 3 "Conventional Control Instruction Parameter Table" for details.

e)  E: Flight control telemetry parameters (30 bytes). See Table 4, 'Flight Control Telemetry Parameter Definition Table,' for field definitions. If no flight control data is available, enter 0.

f)  F: A dedicated command word for gimbal joystick control, 1 byte, as specified in Table 5 "gimbal Joystick Control Command Parameters Table".

g)  G and H: gimbal joystick control parameters (4 bytes), as specified in Table 5, "gimbal Joystick Control Command Parameters Table".

h)  I: Check byte, XOR the lower 8 bits of bytes 3 to 42.

i)  J: Frame-end synchronization code, 1 byte, fixed to F0.

j)  Save the user's last entered data as default parameters in the ini file. The next time you start the application, it will automatically fill in the last parameters.

pay attention to ：

For multi-byte parameters, the lower bits precede the higher bits. All operation commands are transmitted continuously at the communication frequency (using the repeat button). Upon pop-up, the BCDFGH code is reset to zero, and E (telemetry data) continues to send data. Most commands (excluding those requiring consecutive button presses) are received by the terminal, which detects command transition edges to respond accordingly.

Special Control Process of gimbal

1)  gimbal scanning control

The gimbal scan control currently supports yaw scanning only. The scan sequence is as follows:

Initiate scan command 79H 00H 00H 00H 00H (at this point the pan-tilt unit is no longer controlled by external commands).

Set the yaw scan angle to 77H 00H 00H 00H 00H.

Set the platform scanning speed to 79H XXH XXH XXH XXH.

Start scan 79H 00H 00H 00H 00H
